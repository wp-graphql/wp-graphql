# graphql_model_node_context_globals

```php
apply_filters( 'graphql_model_node_context_globals', self::GLOBALS, $model );
```

Filters the globals saved before a model is set up as the current object, and restored when resolution leaves it. The main query ($wp_query) is always saved and restored, separately. By default the list is the post data globals WordPress sets up for a post ($post, $id, $authordata, $page, $pages, $multipage, $more, $numpages, $currentday and $currentmonth). Add a global that setting up the model can change, such as one a plugin sets on the `the_post` action (WooCommerce sets the global $product there) or one a custom model's setup() sets, so fields outside the model's part of the query don't see the value it left behind. The filter runs each time a model is set up, and when a callback is bound to the current node's state, so callbacks should be quick and have no side effects. Globals that hold WordPress's own infrastructure, such as $wpdb, $wp_filter and $current_user, are never saved or restored, even if they're added here.
